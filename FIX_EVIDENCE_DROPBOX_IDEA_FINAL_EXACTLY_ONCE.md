## TEST Failure Summary

TEST proved `idea_create` JSON save/schema/fingerprint/duplicate, but three live runs still lacked `idea_json_final_push_completed`. The failure was the formal LINE final reply proof, not Dropbox JSON persistence.

## Root Cause

The Worker final reply still depended on a timing window between Worker background work and monitor completion visibility. Even after file-write evidence existed, the formal success final was not durable exactly-once.

## Repair

The idea final reply is now monitor-callback driven:

```text
Worker enqueue idea task
  -> task includes task-scoped finalize_token
  -> task includes encrypted line_user_ref, not raw User ID
  -> monitor saves JSON
  -> monitor calls Worker /test/idea-finalize with task id, request id, status, finalize_token
  -> Worker verifies task token and task status
  -> Worker writes idea_json:v1:final:<task_id> state
  -> Worker sends LINE final exactly once
```

Finalizer endpoint:

```text
/test/idea-finalize
```

Guard:

- task-scoped `finalize_token`, generated by Worker and stored only in `_03` remote KV task data.
- no global callback secret value is written to repo.

Exactly-once state:

```text
idea_json:v1:final:<task_id>
```

Final states:

- `sending`
- `completed`
- `failed`
- `suppressed`

Repeated callback behavior:

- `completed` / `sending` / `suppressed` final state prevents a second LINE push.
- duplicate task status writes `idea_json_final_push_suppressed`.
- failed task status writes no success final.

## Safety

- n8n Cloud does not receive local filesystem permissions.
- monitor does not receive LINE access token.
- monitor does not execute arbitrary commands or write arbitrary paths.
- raw LINE User ID is not stored; Worker stores only encrypted `line_user_ref`.
- evidence does not store secrets, raw User ID, signatures, access token, shared secret, or full webhook payload.
